# NOTES.md — OpTrack (repo WheelHouse)

Read NOTES.md first at start of future jobs; keep current; dev only until Marc explicitly approves main.

Notes written 2026-11-08, updated 2026-11-09. No earlier NOTES.md. This is the product source for OpTrack (formerly WheelHouse), the options-wheel tracker (wheels, LEAPs/PMCC, P&L). Live site: https://optrack.app. App shell is `app/`. Go-live checklist is SETUP.md. Payments live in `netlify/functions/` (`checkout.js`, `stripe-webhook.js`). Tests are plain Node under `tests/` (they extract functions from `app/index.html`). Service-worker cache on this branch is `optrack-v200` (`app/sw.js`). A new service worker does not show a refresh banner. A fresh open activates it and reloads once; a session already in use waits for the next open, a navigation, or a return after 30 minutes hidden, and only when no modal or form is open.

## New-visitor simulator

There is no separate dev deploy URL in this repo. `npm run sim` serves `app/` on a local port (the same paths as the live site: `/`, `/start`, `/demo`, `/app/`) and walks a brand-new browser. `npm run sim -- --url https://optrack.app` points it at production.

```
npm install
npm run sim
npm run sim -- --url https://optrack.app
```

Screenshots and `report.md` land in `tools/onboard-sim/out/<timestamp>/`. A step over 5 seconds fails (sign-up, sign-in and delete are allowed 12 seconds, because they wait on Firebase). The simulator sets `localStorage['ot-sim']=1` before any page script, so it does not count in GoatCounter.

GitHub Actions: `.github/workflows/onboard-sim.yml` (workflow_dispatch, optional URL input, artifact upload). The Run workflow button is https://github.com/darcmuff/WheelHouse/actions/workflows/onboard-sim.yml
- Other remote branches exist (`onboarding`, `overhaul`, `skunkworks`). This notes commit does not touch them.


- `dev` (sw v347): Delta at open on the Report and, subtly, on option trade rows and edit forms. A new isolated helper (`app/delta.js`) backs implied vol out of the fill premium (bisection, 1%–500%, fixed 4% rate) and computes Black-Scholes delta. Existing P&L, realised, win/loss, pricing and parsers are unchanged. If IV cannot be solved, delta is left blank. Closed sold options (CSPs, CCs, including PMCC short calls) are bucketed by absolute delta at open (under 0.15, 0.15–0.25, 0.25–0.35, 0.35–0.50, over 0.50, plus No delta), with count, win rate, total and average realised P&L using the same figures and win rule as the Report already uses, and a plain-English best-bucket line. Closed long LEAPs get a small table of the same shape. A typed delta on a wheel trade (`delta`) or a LEAP/short-call (`deltaAtOpen`) overrides the estimate. Stock prices come from a new `histclose` function (Finnhub daily candles, already the app's quote source, with Yahoo as a fallback). When a trade has a fill timestamp in `filledAt`, the function tries 1-minute, then 5-minute, then hourly bars, then the daily close, and the trade-row hover names that precision. OpTrack does not currently store fill times: `entered` / `entryDate` are dates only, `createdAt` and optleg `ts` are save times, and the OpTrack Bot types the trade date into Date Entered through the normal Manual Entry screen. To use intraday prices the bot would need to write `filledAt` (ISO 8601, ideally with a timezone offset) on `users/{uid}/trades/{id}` or `users/{uid}/optlegs/{id}`. The bot was not changed. Main is untouched.
